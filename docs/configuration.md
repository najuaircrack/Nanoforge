# Configuration reference

Generated by python scripts/generate_config_docs.py; verify with --check.
The tables show declared defaults before derived values and presets are applied.
n_kv_heads: null derives from n_heads; ffn_type: null derives from MoE/activation.
Use latticekin validate-config --config <path> before training.
Unknown keys are diagnosed by the loader; release workflows should use strict validation.
All paths in public examples are repository-relative.

## Behavior and implementation limits

- Effective batch is derived from micro batch, gradient accumulation and distributed world size.
- Byte tokenization is a smoke path; real language/FIM quality requires a suitable tokenizer.
- Chat/instruction packing labels assistant or completion targets and records its masking/split policy.
- A nonzero validation fraction requires distinct source groups; no overlapping validation copy is created.
- CPU precision, thread and resource controls must be evaluated on the target machine.
- Paged, chunked, local-block sparse and periodic-global attention have portable reference implementations; optimized native/GPU performance requires separate benchmarks.
- External FlashAttention availability and compatibility determine the selected kernel; names alone are not performance evidence.
- Mamba/RWKV entries are experimental mixers; Sophia-inspired optimization is not the published Sophia-G estimator.
- Int4, GPTQ and AWQ require an implemented external backend; registry names alone do not implement quantization.
- See [training.md](training.md), [architecture.md](architecture.md) and [roadmap.md](roadmap.md) for public workflows and outstanding gates.
